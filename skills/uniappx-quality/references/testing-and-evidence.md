# 测试与证据

## 选择最小充分验证

以下是团队验收基线，不是各商店统一规定。先锁定本次任务范围；“某个页面修复通过”与“全 App 可发布”是不同结论。

| 变更 | 必要验证 | 按风险追加 |
|---|---|---|
| 文案/静态样式 | 受影响布局、目标平台可运行 | 长文本、大字体、产品要求的暗黑/国际化 |
| 状态/导航/表单 | 加载、正常、空、失败、重复触发、离页与返回 | 深链、冷启动、页面恢复 |
| API/异步 | 真实契约、401/非 2xx/业务失败、超时、取消、迟到响应 | 并发、重试幂等、弱网、流式断连 |
| 原生/SDK/权限 | 受影响目标平台编译、实际能力、同意/拒绝/撤回 | 签名白名单、系统版本、前后台 |
| 模式或工具链升级 | 原有基线、目标端编译与主要业务回归 | 插件、CSS、列表、内存、正式包 |
| 发布候选包 | 安装启动、核心流程、权限与数据、升级、签名/版本、商店资料一致性 | 支付/推送/后台、低内存或低版本设备等实际功能 |

自动化参考 [HBuilderX 测试插件](https://uniapp.dcloud.net.cn/worktile/auto/hbuilderx-extension/)。先确认项目类型、插件/依赖、测试文件和目标设备，再按本机及官方帮助执行。不要凭空添加 `npm run test:app`、`vue-tsc` 或 CLI 脚本来证明 App 已通过。脚本确实存在时也要看它实际检查什么。

## 真机与正式包

- 为当前声明支持的 Android、iOS、鸿蒙分别留证。仅对 Web/小程序有变更风险的部分进行兼容性检查，不扩大成完整发布工程。
- 原生模块、权限、签名绑定的 SDK 接入，以项目自有配置的包验证。[项目文档](https://doc.dcloud.net.cn/uni-app-x/project.html) 说明标准基座使用 DCloud 的应用标识、证书与 SDK 配置，它无法证明项目正式签名配置正确。
- 测首次安装、首次启动、覆盖升级和必要的前后台路径。安装失败、白屏、崩溃保留原生日志及复现条件。
- 缺少 iPhone 时可以完成静态核对及可执行测试，但 iOS 必要安装/运行项仍为待验证。Android 签名未准备时，不能称签名发布构建已通过。

## 性能验证

参照 [Vapor 运行注意](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html)：debug 结果不用于正式性能结论，Android 性能应在 release 正式包测试；鸿蒙 release 运行也不完全等同正式包。记录设备、系统、构建、温度/电量及场景，前后对照条件保持一致。

根据产品目标选择指标，例如冷启动、长列表快滑、内存、长时间运行或图片加载。不凭通用经验写死所有设备必须 60/120 FPS；没有测量时只报告现象，不伪造性能数字。复用列表测试滚回后的数据和交互状态，不能只看首屏快慢。

## 报告最小格式

```text
适用条件：提交或源码快照；App版本；平台/设备/OS；模式；工具/SDK；构建类型。
验收范围：本次变更或具体发布候选包。
结果：通过 / 阻塞 / 不适用。
证据：执行时间、命令或手动步骤、实际输出/日志/产物；测试替身明确标注。
问题：严重性、复现步骤、预期/实际、影响范围；待验证项及缺失条件。
下一步：最小修复或补验操作，哪些独立工作可继续。
```

“不适用”写出功能未使用或目标范围不包含等依据。网络失败导致规则未核实、工具缺失或设备缺失均不是不适用。报告不能同时写“阻塞项未完成”和“整体发布验收通过”。

代码、平台或签名变化后引用旧报告时，说明未变化的适用条件并重查受影响内容；不因同一个应用名称就复用不同包的结论。
