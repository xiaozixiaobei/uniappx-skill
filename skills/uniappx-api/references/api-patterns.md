# API 调用与异常处理

## 选择与兼容性

查 [uni.request](https://doc.dcloud.net.cn/uni-app-x/api/request.html) 等具体 API 的当前文档，不将 API 总览的跨端说明当成某参数的保证。记录目标平台、模式、工具与 SDK/插件版本、必需配置、权限和返回类型。参数支持与 API 本体支持分开确认。

若不支持：优先官方替代 API，其次已确认兼容的插件，最后按需求实现平台 UTS 插件。替代会改变功能、成本或平台范围时说明并确认；不能用空函数、静态结果让调用假装成功。普通 uni-app 的 `plus`、浏览器对象和原生语言插件不能默认适用于 uni-app X。

## 网络请求

以下为基于官方请求参数改写的**最小调用模式**，放入项目已使用的脚本环境并验证；不是完整页面、通用 SDK，也未在本技能包中进行 App 编译。

```javascript
const task = uni.request({
  url: 'https://api.example.com/items', // 示例域名，使用已确认的真实接口替换
  method: 'GET',
  timeout: 10000,
  success: (response) => {
    if (response.statusCode === 401) {
      // 交给本工程已有的登录失效处理；不要无限刷新或重放。
      return
    }
    if (response.statusCode < 200 || response.statusCode >= 300) {
      // 进入本工程的 HTTP 错误分支。
      return
    }
    // 此处还需按真实业务契约验证 response.data，不能仅凭 HTTP 2xx 报业务成功。
  },
  fail: (error) => {
    // 本工程的超时、断网、解析或取消错误分支；日志不输出令牌及个人数据。
  },
  complete: () => {
    // 结束当前请求的加载状态，避免覆盖另一个并发请求。
  }
})
// 离开页面或任务失效时，按实际生命周期调用 task.abort()。
```

规则来源：[请求文档](https://doc.dcloud.net.cn/uni-app-x/api/request.html) 的参数、`RequestSuccess.statusCode` 和 `RequestTask.abort()`。10 秒超时和以下重试策略是**推荐实践**，不是官方强制默认值。

- `success` 与 HTTP/业务成功分开判断。401 不当作成功；登录刷新采用项目既有机制，限定次数并处理并发等待，避免刷新循环。
- 默认不增加自动重试。确需重试时只针对确认可安全重放的请求，限制次数、退避并支持取消；创建订单、支付等操作须先确认服务端幂等和结果查询，不能机械重放。
- 页面切换、快速搜索和重复点击需要取消或标识请求；旧响应不得覆盖新状态。监听/流式回调按文档解绑。
- 上传、下载使用对应官方 API，核验路径和格式、鉴权、文件大小、取消与持久化。临时路径不能未经验证就当作永久资源。
- Web 跨域、移动网络、TLS、服务端错误分别定位。不要关闭证书校验来绕过问题。

### Vapor / VDOM 差异

请求文档注明 Android VDOM 的 JSON/泛型受 UTS 约束，默认对象不能照搬 JS 的任意动态属性操作。用项目实际支持的 `UTSJSONObject` 或自定义数据类型，并处理解析/类型转换失败。Vapor 的页面由 JS 驱动，不应将 VDOM 强类型限制生搬过去。

若需要封装，先读已有封装。Android VDOM 的拦截器和泛型传递有专门限制；Vapor 与之不同。一个接口的调用不自动需要拦截器框架。

## 存储、系统与 SDK

| 场景 | 必查项 | 推荐验证 |
|---|---|---|
| 本地存储 | 具体 `uni` 存储 API、数据大小/格式、敏感信息及退出登录清理 | 空值、损坏、升级迁移、容量失败；不默认使用 `localStorage` |
| 文件/媒体 | 临时/持久路径、沙箱、格式、权限和第三方提供方 | 拒绝、取消、无文件、超大文件、应用重启后可用性 |
| 定位/设备/后台 | 权限声明、系统授权、调用时机、后台限制、平台支持 | 拒绝、永久拒绝、服务关闭、前后台切换 |
| 登录/支付/分享/推送 | 模块、SDK 配置、应用标识与签名、服务端契约 | 取消、重复回调、过期、正式签名及正式环境 |

SDK 接入前记录提供方、版本、功能、数据类型、初始化/采集时机、所需权限和披露地址。由隐私流程核验，而不是默认“同意弹窗出现后即可采集”。

Vapor 下 Android 原生调用不能直接留在 `.uvue` 页面，包括 `utsAndroid`；按 [Vapor 文档](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html) 移至 UTS 插件。插件还要分别核对平台、模式、系统版本、构建版本、许可证及维护情况。当前任务只补需要的实现，不引入整套跨平台适配层。

## 验收证据

按实际调用类型选择必要证据：HTTP 调用记录正常数据、401/非 2xx、业务失败、断网/超时、取消/离页及畸形响应；存储/文件调用使用上表的空值、损坏、路径、容量和持久性等相关场景；设备接口核验能力、状态变化及资源释放。本地接口不要求无关的 HTTP/后端测试。涉及权限或 SDK 时补首次同意、拒绝、撤回和必要正式包验证。所需后端、设备或签名缺失时列出未验证路径，不能用 Web/Mock 成功证明真实 App 接入通过。
