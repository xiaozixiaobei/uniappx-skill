## Apple 中国区

官方来源：[审核指南](https://developer.apple.com/cn/app-store/review/guidelines/)、[App 隐私详情](https://developer.apple.com/cn/app-store/app-privacy-details/)、[提交准备](https://developer.apple.com/app-store/submitting/)。

按真实业务检查以下已取得正文的条款：

- 2.1 完整性和审核可用性、2.3 元数据与实际功能一致；提供真实可访问的审核路径。
- 5.1.1 政策入口、数据处理与第三方、适用的账号删除；商店隐私标签按实际 SDK 行为填写。
- 4.8 登录服务及例外；3.1.1 等支付规则结合商品类型、地区和例外逐项核实。
- 1.2 用户内容、1.3 儿童类别等仅在功能/分类触发时检查。
- 2.5.2 动态代码等技术限制；框架热更新能力不自动得到商店许可。

Privacy Manifest、所列 API 原因、SDK 合规、跟踪授权和隐私标签分别核查。截图尺寸、数量、支持设备、年龄分级、当前工具/SDK 上传门槛从相应现行说明及后台确认，不写死在技能中。

本轮 Apple 中文“即将实行的要求”与其他官方页面包含不同年代/生效日的信息。因此不能仅凭页面名称或核验日期声称已确认“最新最低 SDK”；实际发布需按日期复核具体要求。中国区的备案/行业材料按应用实际业务及官方中国区说明核验，不套用海外地区规则。

## 小米

官方来源：[开发者生态政策](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1321)、[权限申请说明](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=2117)。政策正文标注的更新时间为 2025-06-23，本轮读取日期不改变该政策的更新时间。

已取得的政策要求包含兼容稳定、功能/素材真实、最小相关权限、应用身份与签名及版本连续性、符合适用资质/APP 备案要求。应按当前正文和应用类别确认具体材料；不要将一个商店的资质标准提升为所有商店统一规则。

权限申请说明区分**系统权限授权**和**渠道权限申请**：需据包体和真实功能场景准备相应说明/截图或视频，包名及签名应对应实际版本；相关权限申请和应用发布可进入不同审核流程。历史申请结果是否适用于新版，需核对权限集合及当前规则，不默认每次自动继承或全部重新申请。

门户自身的“隐私政策”和“发布协议”不等同于应用隐私审核细则或上传操作文档；引用前核对正文标题和适用主体，不能只看导航链接名。

## 其余渠道的核验入口

- 华为：[开发者联盟](https://developer.huawei.com/consumer/cn/)。选定 Android/鸿蒙后查对应分发/审核文档，核实应用类别和发行形式。
- OPPO：[开放平台](https://open.oppomobile.com/)。定位当前应用分发文档及审核规范，记录正文标题/日期/适用项。
- vivo：[开放平台](https://dev.vivo.com.cn/)。定位当前应用上架、审核及隐私要求，核对实际表单。
- 应用宝：[腾讯应用开放平台](https://app.open.qq.com/)。定位当前移动应用分发规范及相应版本的材料要求。

若公开页面仅有 JavaScript 壳或需要登录，可用用户已授权的该平台会话读取具体文档/表单；不要访问其他业务页面或要求用户提供账号密码。仍取不到时保留明确待核验条目和下一步。
