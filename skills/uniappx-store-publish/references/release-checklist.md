# 共用发布检查

本表是**团队准备基线**，用于收集证据；具体必需项、例外、规格和时限以目标渠道当前官方要求为准。它不宣称所有商店执行完全相同的规范，也不覆盖未选择的 Google Play 或海外地区规则。

## 共用材料与候选包

| 主题 | 收集/检查 | 通过依据 |
|---|---|---|
| 主体和权属 | 开发者主体、联系人、品牌/版权/授权；备案及行业资质按地区/业务核验 | 官方适用要求 + 真实有效材料；不能编造编号或承诺 |
| 应用身份 | DCloud appid 与平台标识分别记录，版本、签名和在架版本关系 | 构建记录与产物检查，身份/签名连续性明确 |
| 候选包 | 正式分发类型、版本、哈希、所需模块/ABI/系统/SDK | 目标渠道接受的格式与当前门槛，实际构建/安装证据 |
| 元数据 | 名称、描述、分类、图标、截图/预览、更新说明、联系/支持入口 | 与候选包实际功能一致；按该店当前尺寸/数量/文件格式制作 |
| 隐私和权限 | 政策、SDK/数据与权限清单、后台披露、同意/拒绝/撤回 | 代码/正式包行为与声明一致；系统权限不由隐私勾选替代 |
| 审核可达性 | 必要的测试账号、步骤、地区/硬件/登录条件、后端服务可用性 | 审核人员能访问实际功能；敏感账号只经授权提供给目标渠道 |
| 质量 | 干净安装、升级、冷启动、核心流程、权限、崩溃及异常 | 质量报告匹配当前候选包，不能引用另一签名/版本的结果 |
| 发布运营 | 发布方式、联系人、监控、服务端兼容及故障处理 | 用户确定的发布范围；上线后按任务需要验证可下载/可运行 |

### 条件触发

- **中国大陆分发**：核验适用的 APP 备案、主体/名称一致性和展示方式。小米官方政策有具体要求，但不能将其条款自动当成其他渠道已核验要求；监管规定追溯主管部门官方来源。
- **创建账号**：核对删除/注销和隐私说明，不把退出登录当作注销；需要保留的数据应有适用依据。
- **第三方登录**：Apple 按当前 4.8 及例外检查适用登录选项，不因任何 SDK 的存在就强制新增某登录。
- **数字内容/订阅/支付**：区分数字和实体商品、地区与服务类型，核对当前支付规则、恢复购买、取消/退款等适用行为。不把国内 Android 支付方案直接套给 Apple。
- **广告/跟踪/个性化**：核对实际数据用途、跟踪判断、授权与披露；不是每个 App 都需要相同弹窗。
- **UGC/社交**：核对适用的内容管理、举报、拉黑、响应和联系机制。
- **未成年人/儿童、游戏或特殊行业**：按真实业务补年龄分级、内容/数据/支付及行业资质；不默认所有 App 都要同一证照。
- **热更新/动态代码**：框架可生成更新包不证明商店允许用其改变功能，单独核验目标渠道政策。

Apple 的具体条款从 [审核指南](https://developer.apple.com/cn/app-store/review/guidelines/) 确认；小米从 [开发者生态政策](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1321) 确认。监管来源未取得正文时仅列核验任务，不依据二手文章补成确定法律要求。

## 发布前的规则核验

对每条影响放行的规则记录：官方 URL/条款标题、渠道/地区/类别、公布及生效日期、核验日期、已生效/未来生效、项目是否触发、证据或缺项。留意公告和正文版本；若不同语言页面/公告冲突，保留差异并通过最新适用官方说明或后台要求核实，不自行选择更宽松版本。

例如，商店上传所需 SDK 不等于最低支持 OS，未来公告不等于当前已经强制。来源不能读取时，允许先准备材料；相关发布准备结论仍为阻塞，并明确需要哪一条正文/后台字段，而不是宣称整包资料无效。

## 回执与驳回处理

提交动作在授权范围内执行并留证：渠道、应用、包哈希、版本、提交时间、材料版本、真实回执/审核编号、当前状态。没有回执则不报提交成功，不为探测状态重复点击提交。

驳回时读取完整原文与附件，核对它指向的应用/版本/平台和条款：复现 → 确定代码/SDK/隐私/素材或资质问题 → 最小修改 → 重新构建/测试受影响项 → 更新材料 → 按授权重新提交。不要只改政策文字掩盖仍存在的数据行为，也不要以不同包名或隐瞒功能绕过审核。

上线后按已约定任务核验状态、下载和关键功能。存在严重问题时按该渠道当前能力和用户授权暂停/调整发布，保持数据和服务端兼容；不假设所有商店都能回滚任意历史包。
