# 工程与模式选择

## 1. 工程证据

先读 `manifest.json` 的 `uni-app-x` 节点及实际 Vapor 设置、HBuilderX 项目识别结果，再读入口和页面。JSON 配置可能含注释，使用已有解析方式或可视化配置，避免用严格 JSON 解析后全量重写。`uni-app-x` 的空节点用于项目类型识别，不代表已启用 Vapor。

新工程按官方 [项目文档](https://doc.dcloud.net.cn/uni-app-x/project.html) 使用 HBuilderX 创建 uni-app X 工程。2026-11-04 的正文注明：5.25+ 新建默认 Vapor；旧版需在创建界面明确选择 uni-app X。通过清单确认模式，不仅依靠默认值。源码位于项目根目录，构建产物在 `unpackage/`；不要默认套用老 uni-app 的 `src/dist` npm 项目组织。

CLI 创建与发行有官方入口，但本轮 [CLI 页面](https://hx.dcloud.net.cn/cli/README) 只返回页面壳；具体命令未核验。自动化任务先取得对应版本的官方正文和本机帮助，再给出完整命令；工具缺失时可以完成配置准备，但不能宣称已创建或编译成功。

主要文件只按用途增改：页面 `.uvue`、路由 `pages.json`、应用与分发配置 `manifest.json`、`App.uvue`、入口 `main.uts/ts/js`、`components/`、`uni_modules/`、静态资源 `static/`。入口扩展名与当前工具版本匹配；项目文档注明 `main.ts/js` 的 Vapor 支持从 HBuilderX 5.31+ 开始。不要为小功能建立多层架构。

## 2. Vapor 支持快照

下表来自 [Vapor 官方文档](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html) 的“体验方式／运行注意”，核验日期 **2026-11-04**，是采用该路线的最低条件快照，不是商店当前提交门槛。

| App 平台 | Vapor 工具门槛 | Vapor OS 门槛 |
|---|---|---|
| Android | HBuilderX 5.21+ | Android 6.0+ |
| iOS | HBuilderX 5.11+ | iOS 15+ |
| HarmonyOS | HBuilderX 5.0+ | API 20+／HarmonyOS 6.0+ |

所有目标平台都要满足条件；再核查具体 API、组件和三方插件，整体平台支持不代表每个属性都支持。若业务必须支持更低系统版本，先说明冲突并评估现有 VDOM 路线或调整范围，不擅自提高最低版本。

正文还说明：当前 Vapor 项目编译到 Web/小程序时以 VDOM 运行。因此“App Vapor、Web 可用”需要分别验证；不能宣称 Web 正在使用同一原生渲染引擎。

## 3. 模式对应的开发约束

| 位置 | Vapor | 已有 VDOM 工程 |
|---|---|---|
| Vue 代码 | 组合式 API；不支持选项式与 mixin | 遵循项目已有且受支持写法，避免因小修复全量转换 |
| 页面语言 | JS 驱动，也可兼容经转换的 UTS 页面；扩展名/语法核对版本 | 按目标平台遵守 UTS 的类型及原生编译限制 |
| Android 原生调用 | 页面中的原生调用（包括 `utsAndroid`）移入 UTS 插件 | 根据现有模式与平台能力核验，不能将原生代码直接扩散至跨端页面 |
| CSS | 运行时简单 class、分组选择器，样式隔离 2.0；细节交给 UI 流程 | 使用本工程支持的选择器和隔离方式，不能将 Vapor 限制误报为所有 VDOM 的限制 |
| 原生 UI 插件 | UTS 标准模式、`native-view`；核查插件兼容声明及真机结果 | 查实际支持矩阵；普通 uni-app 原生语言插件不自动适用于 uni-app X |

条件编译只覆盖实际平台差异；涉及模式差异时核验 `VUE3-VAPOR`。不要用运行时 `if` 包裹导入来代替会参与编译的隔离。记录每个分支的支持平台，并编译其他受影响目标。

开发时复用已有状态、接口和组件；明确异步失败与取消，页面卸载时释放监听、定时器和任务。输入类型、接口数据和空值根据真实契约定义，不把 `any` 当成平台兼容解决方案。

## 4. 迁移与验收

迁移是独立改动：先盘点选项式/mixin、复杂选择器、隔离策略、原生调用和插件，再逐项调整、切换模式并回归。先保留原模式可验证基线；只在用户已明确要求迁移时执行。用户同时要求“小范围修复”和“全量迁移”且交付范围冲突时先澄清。

项目类型、路由、入口或构建配置变化后，至少验证：目标页面可进入；正常、空、加载、失败状态；受影响平台编译；相关导航、事件清理与权限。未安装工具、缺目标设备、版本不明都要说明，不生成假日志。
