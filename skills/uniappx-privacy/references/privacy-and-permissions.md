# 隐私与权限流程

## 工程清单与数据流

以下是本技能包的**工程基线**。法律/商店是否强制某一项，另以适用的当前官方条款核验；不将此清单本身称为统一法律标准。

| 功能/SDK及版本 | 数据类型和用途 | 本地采集/发送时机 | 接收方/服务端 | 权限及必要性 | 保留/删除/撤回 | 实际验证与披露位置 |
|---|---|---|---|---|---|---|
| 按项目实际填写 | 包含 SDK 间接读取、标识符、诊断日志 | 区分初始化、读取、缓存、传输 | 明确第三方 | 只列真实需要项 | 明确对应实现或待核验 | 不以文档声明代替实际行为 |

检查 manifest/原生清单、`uni_modules`、应用启动、登录、媒体/定位等入口，识别 SDK 在应用代码运行前的自动采集。若 SDK 初始化会读隐私数据，不能用“暂不上报”代替延迟采集；按 SDK 官方配置关闭自动初始化或延后加载，并验证正式包。

## uni-app X 隐私机制

来自 [隐私 API](https://doc.dcloud.net.cn/uni-app-x/api/privacy.html) 与 [manifest](https://doc.dcloud.net.cn/uni-app-x/collocation/manifest.html)，2026-11-04 核验：

- 使用 `uni.getPrivacySetting` 查询框架隐私状态；返回的 `needAuthorization` 表示是否仍需授权。先确认目标平台与具体方法的兼容性；Web 不自动拥有 App 隐私 API。
- App 隐私政策界面由项目实现；同意按钮使用官方 `button` 的 `open-type="agreePrivacyAuthorization"`，不要发明 `uni.agreePrivacy()` 或仅写一个 storage 布尔值来冒充框架授权。
- `uni.onPrivacyAuthorizationChange` / `uni.offPrivacyAuthorizationChange` 用于状态监听与解绑；`uni.resetPrivacyAuthorization` 用于确需重新授权的场景，不在每次启动无条件重置。
- `app.initPrivacyAuthorization` 支持 `auto/agree/disagree`。官方文档说明 `auto` 下 Android、鸿蒙初始未同意，iOS 初始同意。因此框架默认 `agree` **不是用户真实同意的证据**。产品要求首启显式同意时，核验初始化策略并测试已同意用户重启后的状态。

最小接入顺序：读取已保存的有效授权 → 需要授权时展示可访问的政策及同意/拒绝入口 → 以真实用户操作完成框架授权 → 再启用需要该同意的数据处理。系统权限在具体功能需要时另行申请。不得把数据事先收集、延后上传描述为“同意前未采集”。

## 三种授权分别处理

| 机制 | 能证明什么 | 不能替代什么 |
|---|---|---|
| 产品/框架隐私授权 | 对相应版本政策的实际同意流程与记录 | 不等于系统定位、相册、相机等权限 |
| 系统运行时权限 | 系统对具体能力的授权状态 | 不等于全部数据用途获同意或 SDK 已正确披露 |
| iOS 跟踪相关授权 | 适用场景下按 Apple 当前要求取得的跟踪授权 | 不由普通隐私弹窗替代；也不因用了任意统计就无条件要求弹窗 |

拒绝后停止无条件重复弹窗；能降级时提供手动选择/不使用该功能。确属功能必要条件时说明影响，并由用户主动重试或进入设置；不要把所有应用功能都锁到无关权限上。

## 文本与声明的一致性

核对政策中的主体、用途、数据、SDK、第三方、保留/删除、联系与撤回方式，和实际代码、后台表单保持一致。不要复制其他应用政策并擅自填入主体信息。

Apple 的 [审核指南 5.1.1](https://developer.apple.com/cn/app-store/review/guidelines/#privacy) 与 [App 隐私详情](https://developer.apple.com/cn/app-store/app-privacy-details/) 适用于相应 Apple 分发任务：检查 App 内及元数据的政策入口、第三方 SDK 行为和隐私标签。支持创建账号时，核对当前账号删除要求及适用例外，区分退出登录与删除账号/数据。

隐私标签、Privacy Manifest、所列 API 的 approved reason、SDK 要求和跟踪授权是不同事项；按实际使用的 API/SDK及当前官方文档分别确认，不用单一表单替代全部检查。涉及国内渠道的具体披露项时调用商店流程，未取得条款正文的渠道不能宣称已合规。

## 行为验收

1. 干净安装未操作时：哪些 SDK 已初始化、读取、缓存或发送？在 Android/iOS/鸿蒙分别验证，不从默认状态推导。
2. 拒绝隐私、拒绝功能权限、永久拒绝、服务关闭：不循环弹窗，功能反馈清楚，数据处理与用户选择一致。
3. 同意及重启：需要的功能恢复，授权状态保留，无重复初始化。
4. 撤回或政策重要变化：按需要停止处理、解绑监听、处理缓存和重新同意，不仅改一个 UI 开关。SDK 不支持停止时说明限制并解决相关数据路径。
5. 注销：实际触发账号/数据处理，按业务和适用要求说明需保留的数据，不伪造服务端删除完成。

网络观测需覆盖原生 SDK 和真实签名包；只看 JS 请求日志可能遗漏数据行为。无设备或无可观测证据时记录待验证，不能据静态审查直接给出动态行为通过结论。
