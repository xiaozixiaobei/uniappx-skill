# 技能行为验收场景

结构检查用 `python3 -m unittest discover -s tests -v`。下列场景需独立助手或人工实际读取技能演练；仅检查关键词不能作为通过。读者应检查实际判断、加载范围、依据和证据边界，不按输出措辞评分。

验收时只向受试者提供任务与必要工程事实，先加载总控并让其选择流程，不提前给期望答案；本表的期望用于验收者评分。测试不联网、不真实上传、不打包 App，不据演练宣称原生功能已验证。

| 编号 | 任务/工程条件 | 期望行为 |
|---|---|---|
| S01 | 新建三端 App，HBuilderX 5.20，最低 Android 5/iOS 14/鸿蒙 API20，要求 Vapor | foundation；识别工具和最低 OS 冲突，说明调整/替代，不静默提高最低版本 |
| S02 | 既有 VDOM 只修空状态 | 识别模式、最小 UI 修复及必要回归，不顺带迁移 |
| S03 | request success 返回401，订单超时要求重试3次 | API；分开传输/HTTP/业务结果，写操作先核对幂等/结果查询 |
| S04 | Vapor 两组 list-item v-for，item 封进子组件，CSS 用层级选择器 | UI；稳定 key、首组循环、同文件、简单 class/隔离规则，验证状态复用 |
| S05 | iOS 首装框架默认已同意，直接启动采集 SDK | privacy；区分默认状态与真实同意，检查初始化采集及平台策略 |
| S06 | 拒绝定位后反复弹窗，新增撤回隐私开关 | API/privacy；功能触发、降级/主动重试；实际停止相关数据行为和解绑 |
| S07 | Web通过，无iPhone、无Android签名，要求发布测试通过 | quality/build；区分已验证与待验证，不宣称 App 验收通过 |
| S08 | 三端同一云打包命令，CLI文档只有壳 | build；Android/iOS 与鸿蒙分支，先核验工具，不发明命令 |
| S09 | Android自定义调试基座APK上架 | build/store；识别基座用途，需要正式候选包、签名及验证 |
| S10 | Apple中国区和小米统一清单，不联网，写死最新SDK并提交 | store；共同准备+渠道差异、动态门槛待核验、按具体授权处理对外动作 |
| S11 | 华为/OPPO/vivo只能打开入口，报告三店准备完成 | store；入口不等于条款，相关渠道准备不能通过，其他材料继续 |
| S12 | 昨日测试后更换SDK、重签名、增加渠道包 | 按新包/哈希和受影响数据/签名能力重验，不全盘沿用旧证据 |
| S13 | 单独加载 API 技能接入文件上传 | 自身入口/参考可用；需要时找到本包 privacy，不依赖旧安装技能 |
| S14 | 总控存在但目标子技能文件缺失 | 明确缺少技能名、受影响任务，不能静默回退到旧 uni-app 规则 |
| S15 | 公告下年才生效，中文页面仍是历史SDK门槛 | store；分别核对公布/生效日期和当前要求，不能把未来门槛当当前或用旧页定最新 |
| S16 | 只修离线存储的空值，无网络调用 | API；选择存储类型的证据，不要求 HTTP401 或后端环境 |
| S17 | 仅暴露根兼容入口描述，用户请求证书检查、隐私审查或提审材料 | 根入口描述可发现相关任务，读取正式总控并路由 |
| S18 | 当前版本单平台 UI 小改动，必要编译/真机证据齐全，仅有可选重构建议 | 本次范围可通过，不因风格建议或未选择的其他平台阻塞，不扩大为整体发布通过 |

每次验收记录实际加载文件、处理方案、结果、缺项与错误；发现问题仅修正相关指令并重测受影响场景。
